# CI troubleshooting

## Current release blocker: application dependency installation

The most recent verified pull-request CI run for the tenancy hardening branch completed with the following results:

- Collector validation: passed
- Shell-script syntax validation: passed
- Application validation: failed during dependency installation
- Prisma validation, Prisma client generation, tenancy tests, type-checking, and application build: skipped because dependency installation failed

## Toolchain alignment applied

The release branch now pins the same application toolchain used by the production Docker build:

- Node.js 22
- Yarn 4.9.2 through Corepack
- `nodeLinker: node-modules`
- immutable lockfile installation

`nextjs_space/package.json` declares `packageManager: yarn@4.9.2`, and CI explicitly activates that version before installation.

## Clean-database migration validation

The application CI job now starts PostgreSQL 15 and executes the complete migration chain against an empty `threatpulse` database:

```bash
yarn prisma migrate deploy --schema=./prisma/schema.prisma
yarn prisma migrate status --schema=./prisma/schema.prisma
```

This validates the clean-install migration path before tenancy tests, type-checking, and application build.

A separate production-upgrade rehearsal is still required using a sanitized backup or a schema clone representative of the currently deployed database.

## Required diagnosis if immutable installation still fails

Capture the complete dependency-manager error and verify all of the following:

1. `nextjs_space/package.json` package-manager metadata remains `yarn@4.9.2`.
2. `nextjs_space/yarn.lock` was generated by the same Yarn major version used in CI.
3. `nextjs_space/.yarnrc.yml` remains compatible with the lockfile and CI environment.
4. CI does not depend on committed `node_modules` content.
5. Dependency installation succeeds from a clean checkout with an empty cache.
6. The lockfile remains unchanged after installation.

## Local validation commands

Run from a clean checkout:

```bash
cd nextjs_space
corepack enable
corepack prepare yarn@4.9.2 --activate
yarn --version
yarn install --immutable
yarn prisma validate --schema=./prisma/schema.prisma
yarn db:generate
yarn prisma migrate deploy --schema=./prisma/schema.prisma
yarn prisma migrate status --schema=./prisma/schema.prisma
yarn test:tenancy
yarn tsc --noEmit
yarn build
```

Do not weaken the CI gate by removing immutable installation unless the lockfile is intentionally regenerated and reviewed.
