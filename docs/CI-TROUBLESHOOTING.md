# CI troubleshooting

## Current release blocker: application dependency installation

The most recent verified pull-request CI run for the tenancy hardening branch completed with the following results:

- Collector validation: passed
- Shell-script syntax validation: passed
- Application validation: failed during dependency installation
- Prisma validation, Prisma client generation, tenancy tests, type-checking, and application build: skipped because dependency installation failed

## Required diagnosis

On the release branch, reproduce the application job from `.github/workflows/ci.yml` and capture the full dependency-manager error. Verify all of the following:

1. `nextjs_space/package.json` package-manager metadata matches the intended Yarn version.
2. `nextjs_space/yarn.lock` is generated by the same Yarn major version used in CI.
3. `nextjs_space/.yarnrc.yml` is compatible with the lockfile and CI environment.
4. CI does not depend on committed `node_modules` content.
5. Dependency installation succeeds from a clean checkout with an empty cache.
6. The lockfile remains unchanged after installation when immutable installation is required.

## Validation commands

Run from a clean checkout:

```bash
cd nextjs_space
corepack enable
yarn --version
yarn install --immutable
yarn prisma validate
yarn prisma generate
yarn test:tenancy
yarn tsc --noEmit
yarn build
```

Do not weaken the CI gate by removing immutable installation unless the lockfile is intentionally regenerated and reviewed.
